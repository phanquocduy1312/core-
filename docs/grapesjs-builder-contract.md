# GrapesJS Visual Page Builder Architecture & Schema Contract (v1.0.0-freeze)

## 1. Core Architecture Overview

```
Page Model (MariaDB / Spatie Translatable)
├── builder_data (JSON per locale: { "vi": {...}, "en": {...}, "ko": {...} })
│   └── Canonical GrapesJS Project Data (Single Source of Truth for Editor)
├── published_html (HTML per locale)
│   └── Clean semantic HTML with runtime data-page-block placeholders
├── published_css (CSS per locale)
│   └── Clean CSS Composer rules & responsive media queries
├── schema_version (Integer: 1)
├── published_at (Timestamp)
└── page_revisions (History snapshots of builder_data, published_html, published_css)
```

### Three-Stage Rendering Pipeline

1. **Stage A: Canonical Project Data (`builder_data`)**
   - Stores ONLY structural component tree and canonical component configuration.
   - Never contains ephemeral preview DOM children, database snapshots (prices, titles, post content), or duplicate runtime data-* attributes.
2. **Stage B: Stored Staging HTML (`published_html`)**
   - Generated by Centralized Serializer (`DynamicBlockConfigValidator` / `GrapesDynamicBase.serializeConfigToHtml`).
   - Cleaned by strict whitelist `PageHtmlSanitizer`.
   - Contains safe semantic markup and `<div data-page-block="...">` placeholders.
3. **Stage C: Public Live Output (Frontend Response)**
   - `PageBlockRenderer` intercepts `data-page-block` placeholders and dynamically resolves real, live database records (Products, Posts, Reviews, Partials) at request time.
   - Zero GrapesJS JavaScript/CSS loaded on public pages.

## 2. Canonical Component Schema Definition

### A. Basic Layout & Content Components (M3)

#### 1. Heading (`builder-heading`)
```json
{
  "type": "builder-heading",
  "tagName": "h1",
  "role": "section-title",
  "content": "Tiêu Đề Trang Sang Trọng",
  "classes": ["hero-title"]
}
```

#### 2. Paragraph (`builder-paragraph`)
```json
{
  "type": "builder-paragraph",
  "tagName": "p",
  "role": "section-description",
  "content": "Mô tả nội dung chi tiết..."
}
```

#### 3. Button / Link (`builder-button`)
```json
{
  "type": "builder-button",
  "tagName": "a",
  "role": "primary-action",
  "content": "Xem Chi Tiết",
  "attributes": {
    "href": "/vi/pages/lien-he",
    "target": "_self"
  },
  "classes": ["builder-btn", "btn-primary"]
}
```

#### 4. Image (`image`)
```json
{
  "type": "image",
  "mediaRef": "media:yachts/majesty-120-hero.jpg",
  "attributes": {
    "src": "https://sontungyacht.com/storage/media/yachts/majesty-120-hero.jpg",
    "alt": "Du Thuyền Majesty 120",
    "loading": "lazy"
  },
  "classes": ["hero-img"]
}
```

#### 5. Layout Containers (`builder-section`, `builder-container`, `builder-grid`, `builder-columns`, `builder-column`, `builder-stack`)
```json
{
  "type": "builder-section",
  "classes": ["builder-section", "section-hero-01"],
  "components": [
    {
      "type": "builder-container",
      "classes": ["builder-container"],
      "components": [...]
    }
  ]
}
```

### B. Predefined Section Patterns (M4 / M4.1)

All section patterns are pure compositions of M3 Basic/Layout components:
- Supported `sectionType`: `hero`, `about`, `services`, `projects`, `gallery`, `cta`, `contact`.
- Supported `variant`: `hero-01`, `hero-02`, `about-01`, `about-02`, `services-01`, `services-02`, `projects-01`, `projects-02`, `gallery-01`, `gallery-02`, `cta-01`, `cta-02`, `contact-01`, `contact-02`.

```json
{
  "type": "builder-section",
  "sectionType": "hero",
  "variant": "hero-01",
  "classes": ["builder-section", "section-hero-01"],
  "components": [...]
}
```

## 3. Strict Attribute Sanitization & Security Boundary

`PageHtmlSanitizer` enforces a strict whitelist of allowed runtime `data-*` attributes:
- `data-page-block`
- `data-category`
- `data-limit`
- `data-query`
- `data-columns`
- `data-gap`
- `data-align`
- `data-partial-id`
- `data-tab`
- `data-cat`

All other data attributes (`data-gjs-*`, `data-random-*`, `data-editor-*`), script tags, inline event handlers (`onclick`, `onerror`, etc.), and unsafe URL protocols (`javascript:`, `data:`) are permanently purged.

---

## 4. Schema Versioning & Forward Migration Policy

- **Current Version:** `schema_version = 1`.
- Any importer or external tool creating Project Data must specify `schema_version = 1`.
- Future schema evolutions will provide non-destructive migration scripts upgrading `schema_version: N -> N+1` during PageBuilderService load/save cycles.
